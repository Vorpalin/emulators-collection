# Security Policy

## Supported Versions

Security fixes are provided for the latest version of the project available on the `main` branch.

Older versions may not receive security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in **Emulators Collection**, please do not open a public GitHub issue.

Instead, report it privately through GitHub's **Private Vulnerability Reporting** feature or by contacting the maintainers directly.

Please include, when possible:

- A clear description of the vulnerability
- The affected component or emulator
- Steps to reproduce the issue
- The potential security impact
- Any relevant logs, screenshots, or proof-of-concept code

We will review the report and investigate the issue as soon as possible.

## Scope

Security reports related to the following components are welcome:

- The emulator core and system implementations
- The WebAssembly interface
- The web interface
- ROM/game loading and handling
- The build and release infrastructure
- Dependencies that could directly affect the project's security

Issues that are purely related to emulator accuracy or compatibility, without a security impact, should be reported through the regular GitHub issue tracker.

## Disclosure

Please allow reasonable time for a vulnerability to be investigated and, when appropriate, fixed before publicly disclosing it.

Once a fix is available, the vulnerability may be disclosed through the project's GitHub Security Advisories.

Tell them where to go, how often they can expect to get an update on a
reported vulnerability, what to expect if the vulnerability is accepted or
declined, etc.
